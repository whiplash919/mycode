# 4 周渐进式迁移计划

如果你已经有一个杂乱的 vault，**不要推倒重来**。按以下节奏渐进式整理，每周只做一件事。

---

## 第 1 周：建结构，不动旧内容

**目标**：搭好骨架，让新笔记从今天起就进对地方。

- [ ] 创建 7 个顶层文件夹（见 `vault-structure.md`）
- [ ] 在 `06 - SYSTEM/templates/` 放入本仓库 `templates/` 下的全部 8 个模板
- [ ] 在 `06 - SYSTEM/dashboards/` 放入 `dashboards/` 下全部仪表盘文件
- [ ] 安装并配置插件：Templater、Dataview、Daily Notes
  - Templater 模板目录指向 `06 - SYSTEM/templates/`
  - Daily Notes 模板指向 `06 - SYSTEM/templates/daily.md`
  - Daily Notes 输出目录指向 `01 - NOTES/daily/`
- [ ] 打开 `dashboards/inbox.md` 和 `dashboards/active-projects.md`，确认 Dataview 能渲染（即便目前是空的）

**这周不要碰旧笔记**。让新结构和旧内容并存。

---

## 第 2 周：每条新笔记走新流程

**目标**：建立肌肉记忆，让"按规范创建笔记"成为默认动作。

- [ ] 每条新建笔记都用 Templater 调用模板（不空白起手）
- [ ] 每条新笔记都按 `YYYY-MM-DD-[type]-[topic].md` 命名
- [ ] 每条新笔记都填好 `type / status / date / tags` 四个字段
- [ ] 不确定归属的笔记一律进 `00 - INBOX/`
- [ ] 每天结束前 15 分钟清空 INBOX（处理流程见下文）

**仍然不要碰旧笔记**。这周只是养习惯。

---

## 第 3 周：处理 INBOX 积压 + 高价值旧笔记

**目标**：把进入新系统的笔记数量加速到临界质量。

- [ ] 把所有未归类的旧笔记移到 `00 - INBOX/`
- [ ] 每天处理 10–20 条 INBOX 笔记（不要一次性全做完，会疲劳）
- [ ] **优先处理你过去 30 天打开过的笔记**（这些是活跃知识）
- [ ] 其他旧笔记可以一直留在 INBOX 直到第 2 个月

### INBOX 处理三问
对每条笔记问：
1. **这是什么类型？** → 决定顶层文件夹
2. **它已经有家了吗？** → 是否已有项目/主题与它关联？
3. **它该独立成文，还是应该并入已有笔记？**

然后：
- 补齐 YAML properties
- 改名为 `YYYY-MM-DD-[type]-[topic].md`
- 移动到正确文件夹

---

## 第 4 周：标签清洗 + 第一个 MOC

**目标**：从"分类整齐"升级到"网状互联"。

- [ ] 列出当前 vault 所有标签（Obsidian 标签面板）
- [ ] 删除使用次数 < 5 的标签
- [ ] 用前缀重组：主题（无前缀）、`status/`、`project/`
- [ ] 选出你写得最多的主题（笔记数 > 20），用 `MOC/_MOC-template.md` 创建第一个 MOC
- [ ] 把该主题下所有重要笔记链接进 MOC

---

## 第 2 个月：扩展与深化

- 把剩余 INBOX 处理完
- 创建 2–3 个新的 MOC
- 给最重要的 50 条笔记反向加上完整的 properties

---

## 第 3 个月：第一次季度复盘

### 复盘清单（30 分钟–2 小时）

#### 1. 文件夹审计
- [ ] 每个文件夹是否仍代表你活跃使用的类别？
- [ ] 是否有少于 5 条笔记的文件夹？→ 合并或删除
- [ ] 是否有文件夹层级过深（>3 层）？→ 扁平化

#### 2. 标签审计
- [ ] 所有标签是否仍然相关？
- [ ] 是否有标签只出现在 1–2 条笔记？→ 删除
- [ ] 是否有累积超过 20 条笔记的主题？→ 给它建 MOC

#### 3. 归档扫描
- [ ] `02 - PROJECTS/` 里是否有 `status=complete` 的项目？→ 移到 ARCHIVE
- [ ] `01 - NOTES/daily/` 里是否有超过 1 年的日记？→ 移到 ARCHIVE
- [ ] RESOURCES 里是否有过时但仍链接的资料？→ 移到 ARCHIVE 而非删除

#### 4. 命名一致性
- [ ] 用文件浏览器扫一遍所有笔记
- [ ] 不符合 `YYYY-MM-DD-[type]-[topic].md` 的批量重命名
- [ ] 用 Obsidian 的"Find and replace in all files"或外部工具批处理

---

## 关键心态

> **vault 不会在你实施系统的当天变得完美整齐。**
> **它会在你每周使用系统的过程中变得越来越整齐。**

6 个月后回头看，曾经让你沮丧的 vault 会变成可信赖的系统。

每条笔记都能找到。每个信息需求都能满足。每次检索都在 30 秒以内。

---

## 失败模式（避免这些）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 一周末重组全部旧笔记 | 累垮、放弃、回到旧习惯 | 4 周渐进，每周一件事 |
| 创建 15+ 顶层文件夹 | 找东西时不知道点哪个 | 严格保持 7 个顶层 |
| 标签随手就加 | 累积上百个无用标签 | 5 条笔记规则 |
| Properties 字段越加越多 | 填写疲劳，最后都不填 | 通用 4 字段 + 类型专属字段，到此为止 |
| 把 INBOX 当永久储藏室 | INBOX 变成另一个垃圾堆 | 每日 15 分钟雷打不动 |
| 删除旧笔记腾空间 | 误删将来需要的内容 | 一律归档，不删除 |
